# hmyLaser32 Web Portal

The web portal is the online extension for hmyLaser32. It receives bridge data
from the ESP server, stores matches in PostgreSQL, provides player accounts with
NFC tokens, and displays live match statistics.

## Tech Stack

| Layer | Choice |
|---|---|
| Framework | Next.js 14 App Router |
| Language | TypeScript |
| Database | PostgreSQL |
| ORM | Prisma 5 |
| Auth | iron-session + argon2 |
| Realtime | custom `server.mjs` with WebSocket support |
| i18n | `next-intl` |
| Styling | hmyDesign CSS tokens and `hmy-*` classes |

## Environment

Required `.env` values:

```env
DATABASE_URL=postgresql://user:password@localhost:5432/hmylaser32
SESSION_SECRET=0123456789abcdef0123456789abcdef
NEXT_PUBLIC_DEFAULT_LOCALE=de
```

`SESSION_SECRET` must be at least 32 characters.

## Database Model

Core entities:

| Model | Purpose |
|---|---|
| `User` | registered player account with generated `nfcToken` |
| `EspServer` | registered ESP bridge, PIN, defaults, known player snapshot |
| `Match` | active or finished match for one server |
| `MatchPlayer` | per-player match aggregate |
| `Team` | match team metadata and color |
| `HitEvent` | chronological live hit feed |

Current ESP server defaults include:

- `mode`: `free-for-all` or `team`
- `lobbySeconds`
- `matchSeconds`
- `hitPoints`
- `teams`
- `startRequested`
- `knownPlayers`

After adding or changing Prisma fields, create/apply a migration or run:

```bash
npx prisma db push
```

## Live Match View

The match page shows:

- match status and remaining time
- server online state
- leaderboard
- `Shots`
- `RX Hits`
- `Punkte`
- live feed of hit events

The old K/D-oriented display was replaced for the current firmware flow because
the ESP clients now report shots and received hits directly.

## Bridge Authentication

ESP bridge calls authenticate with:

```http
Authorization: Bearer <server-pin>
```

The PIN is generated by the ESP server and shown in the local captive portal.

## Bridge API

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/api/bridge/register` | register/rebind ESP server |
| `GET` | `/api/bridge/register` | heartbeat |
| `GET` | `/api/esp/by-pin/settings` | ESP pulls match defaults and start flag |
| `POST` | `/api/bridge/match/start` | create active match |
| `POST` | `/api/bridge/match/end` | finish active match |
| `POST` | `/api/bridge/hit` | store live hit event |
| `POST` | `/api/bridge/players` | store known/live player snapshot |
| `GET` | `/api/bridge/player/[nfcToken]` | resolve NFC token to user |

### `POST /api/bridge/match/start`

```json
{
  "mode": "team",
  "durationSeconds": 300,
  "hitPoints": 10,
  "teams": [
    { "name": "Team 1", "color": "#dc2626" },
    { "name": "Team 2", "color": "#2563eb" }
  ]
}
```

Returns:

```json
{ "matchId": "...", "teams": [] }
```

### `POST /api/bridge/hit`

```json
{
  "matchId": "...",
  "shooterNfc": "uuid-or-nec-token",
  "targetNfc": "uuid-or-nec-token",
  "points": 10,
  "shooterHits": 3,
  "shooterDeaths": 1,
  "shooterShots": 12
}
```

`targetNfc` increments the target player's received-hit/death counter.

### `POST /api/bridge/players`

```json
{
  "players": [
    {
      "name": "Alice",
      "command": 1,
      "playerId": 16711935,
      "points": 20,
      "shots": 14,
      "rxHits": 2,
      "team": 1,
      "color": "#dc2626",
      "nfcToken": "uuid-token",
      "lastSeenSec": 0
    }
  ]
}
```

When an active match exists for the server, this endpoint upserts
`MatchPlayer` rows so the browser can see live aggregate stats even when not
every hit event arrived.

## ESP Settings API

`GET /api/esp/by-pin/settings` returns:

```json
{
  "mode": "free-for-all",
  "lobbySeconds": 60,
  "matchSeconds": 300,
  "hitPoints": 10,
  "teams": [],
  "startRequested": false
}
```

`startRequested` is consumed atomically by the ESP server.

## NFC Accounts

Each user has an `nfcToken`. Cards should contain:

```text
username|nfcToken
```

The ESP client uses the username as display name and forwards the token through
the server so match rows can be linked to the account.

## Verification Checklist

- `npm run build` succeeds with a valid `SESSION_SECRET`.
- Prisma Client is generated from the local Prisma 5 dependency.
- New databases contain `EspServer.hitPoints`.
- `/api/bridge/players` accepts `shots`, `rxHits`, `team`, `color`, and
  optional `nfcToken`.
- `/match/[id]` shows Shots/RX Hits/Punkte.
- ESP server settings pull includes `hitPoints`.
- Existing ESP server PINs still authenticate bridge calls.

## Notes For Agents

- Keep bridge contracts documented here when changing API routes.
- Do not assume the ESP server persists player rosters; it only pushes the
  current observed state.
- Prefer backwards-compatible API additions over renaming existing fields.
- Keep UI classes aligned with the existing `hmy-*` and `hmy-lt-*` CSS system.
